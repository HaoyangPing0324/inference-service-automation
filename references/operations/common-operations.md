# 常用远端操作

本手册记录推理服务任务中已经验证过的常用操作短路径。执行资源检查、容器生命周期管理或端口清理前先读本文件，优先复用这里的步骤，避免对同一问题反复宽泛探测。

本文件中的 shell 命令仅在已确认的远端 Linux 主机上执行。连接发起端可能是任意操作系统；Skill 不规定其 shell、路径格式或本地复制命令，连接与传输使用调用端实际可用的等价能力。

所有命令都使用 `environment.toml` 中的实际 SSH 目标、容器名、端口和 PID 替换占位符。记录遵循[实验记录](../project-contract.md#实验记录)：普通查询/停止容器不逐条写LOG，只有影响实验的决策、持续问题与关键验证值得保留；不得记录凭据。

## 通用执行顺序

1. 将 `server.hosts[].address` 视为不透明的 SSH 目标并原样交给 `ssh`。直连、单级跳板或多级跳板由使用者的 SSH 配置与运行环境决定；不得根据当前机器经验自行增加、删除或改写中转路径。若目标无法连接且配置没有表达所需路径，报告配置缺口，不猜测连接拓扑。
2. 用一次只读检查确认目标的当前状态和归属。
3. 只对用户授权的准确对象执行一次最小变更。
4. 用一次统一检查验证最终状态；警告或审批超时不能直接当作成功或失败。
5. 需要接续时更新当前状态；只有影响实验的异常/决策写简短结论和证据入口，不复制常规操作流水。

## 模型下载：execute负责，优先ModelScope

原计划从huggingface.co下载的模型，直接在ModelScope查找对应检查点并下载，不先尝试huggingface.co，也不先尝试hf-mirror.com；不做三站连通性/测速或先等HF超时。此规则仅改变模型文件下载首选站，不禁止从已知官方入口读取模型说明，也不适用于数据集、镜像或其他软件。

- 下载由对应精确卡型的execute在已指定目标机器、模型存储目录执行；一级/二级只确认授权与派工，design不下载、不为普通下载短命令预先写脚本，analyze不参与。下载完成向直属调度回报仓库/实际revision、目标目录、完成或失败及必要大小摘要。
- 使用目标环境已有工具和已配置访问方式。已授权下载该模型且目标目录明确时，采用ModelScope不再作为“换源”重复请求批准；尚未授权下载、需新装下载工具、缺目标目录或涉及额外权限/成本时按已有边界处理。本次Skill修改不直接触发任何真实下载。
- 核对ModelScope仓库的发布方、精确模型/量化变体与所需版本，不因同名就宣称与HF逐字节一致。可按模型卡、config、权重索引及已有摘要确认；不为了比较而额外访问HF、下载两份权重或全面审计。平台revision/commit并不通用，不把HF commit直接当ModelScope revision；版本对应无法确定时报告具体缺口。
- ModelScope没有对应模型、所需版本缺失或下载失败时，报告具体问题，不自动回退HF/hf-mirror或替换模型/精度。用户明确指定其他站或允许后备来源时按其指令执行。
- 下载用独立暂存目录或已有工具的可靠断点能力，完成后确认本次必需权重、索引、config和tokenizer可读且分片齐全，再发布为服务模型路径。不将半下载当完成，不覆盖已有有效模型，不把权重回收本地交付区。
- 不固化某次模型的分片数、文件大小、速度或并发数。ModelScope额外平台元数据不单独构成检查点不一致，但权重、配置或tokenizer差异不能忽略；没有可比证据不声称“逐文件完全一致”。

## 部署镜像：列出现有候选，由用户选择

用户尚未明确选定镜像时，由对应execute在本次目标机器上只读列出现有相关镜像，经二级交一级向用户展示候选与建议，然后等待选择；不能以“最小启动”省略镜像选择。用户已经在指令或本实验配置中明确选定镜像时直接沿用，不重复询问；模板/example默认值、AI自己填写的候选及历史其他实验用过的镜像不算本次用户选择。

- 候选表包括目标机器、完整repository:tag、短image ID或digest、大小、从标签/已有元数据能确认的平台/框架版本，以及推荐与理由。相同ID的多个tag可合并展示；只筛本次相关候选，不铺无关镜像或输出含凭据的完整inspect环境变量。
- 建议优先与已收录平台/框架参考版本匹配、目标平台适用且本机已有的镜像；说明可免下载或需验证的关键限制。标签只能说明命名，未经实际运行不能声称内部版本/模型兼容已验证。不为推荐先启动模型、逐个审计镜像内部或做全量测速。
- 即使只有一个合适的现有候选，也列出并建议使用，等待用户选择；用户已授权“你选/用推荐项”等则直接按授权选择并简短告知。多节点分别标出可用性，不能假设同tag在不同机器内容相同。
- 没有合适现有镜像时明确说明，给出官方推荐镜像、版本与需要拉取的目标机器，询问是否拉取。未获授权不拉取、构建、升级或切换；用户选定的镜像不可用时报告并给备选，不默默替换。
- 用户选择后，design记录到远端experiment.toml和内部运行配置，execute据此创建容器。镜像实际digest/内部版本随容器运行按需记录；此后同一选择不在每个阶段重复问，只有需变更镜像时再确认。

## 资源闲忙查询的默认汇报

用户询问“查询所有资源”“服务器闲忙”等状态时，先重新读取工作区 `servers.toml`，检查全部登记目标，不沿用旧机器清单；连接路径遵循当前配置和用户明确指令。只做只读检查，不停止任务。说明采样时间，默认只输出一张表：

| 服务器 | 加速卡闲忙 | 显存情况 | 当前任务／占用者 |
|---|---|---|---|
| 配置中的机器名 | 空闲卡编号/数量，或全部占用/未知 | 能查到时列已用/总量；同类卡可按编号分组、以范围简述，NPU注明HBM按卡或芯片统计 | 服务/模型与已确认用户；不能确认则明确未确认 |

显存可查询时展示；无法获取写“未查到”及必要的简短原因，不估算或伪造。无法连接的机器也保留一行，状态标未知；不要把连接成功或瞬时利用率0%当作空闲，必须结合显存和计算进程。默认不追加CPU负载、系统内存、磁盘、完整进程命令、PID清单或无关扩展表，除非用户明确要求。需要的进程与归属证据可只读核查，但不在普通闲忙表中铺开。正在执行部署等任务且发现阻塞性资源冲突时，另按完整冲突报告规则汇报，不能以精简查询表取代必要证据。

## GPU 占用与任务归属

先采集 GPU、计算进程和进程归属：

```bash
nvidia-smi --query-gpu=index,uuid,memory.used,memory.total,utilization.gpu --format=csv,noheader,nounits
nvidia-smi --query-compute-apps=gpu_uuid,pid,used_memory --format=csv,noheader,nounits
ps -o user:24,pid,ppid,etimes,args -ww -p <PID列表>
cat /proc/<PID>/cgroup
```

- 先通过 GPU UUID 对应设备编号，再把 PID 对应到用户、父进程、完整命令和容器。
- 多卡训练或服务按完整任务追溯，不能只处理其中一个 worker PID。
- 需要确认容器归属时使用窄化输出，避免无差别输出可能含凭据的环境变量：

```bash
docker ps --no-trunc --format '{{.ID}}|{{.Names}}|{{.Image}}|{{.Command}}|{{.Status}}|{{.Ports}}'
docker top <容器名或ID> -eo user,pid,ppid,etimes,args
docker inspect --format '{{range .Mounts}}{{.Source}}->{{.Destination}};{{end}}' <容器名或ID>
```

资源不足时必须按主 Skill 的格式立即汇报官方需求、当前可用、准确缺口，以及每个冲突对象的机器、资源、用户、PID/容器、服务和影响。用户授权前只读检查，不清理他人任务。

## 端口与容器定位

### 单文件bind mount的配置版本

宿主机文件被原子替换后，已有容器的单文件bind mount可能仍指向旧inode。执行新协议前比较容器实际读取配置与宿主源的摘要，不能只确认宿主文件已更新。发现不一致时，只对本实验选择正常重建空闲容器，或把已校验配置复制为容器内本轮只读快照并通过既有EXPERIMENT_ENV指定；记录路径和摘要，不覆盖用户设计表、不修改普通benchmark参数。重启有影响的运行服务或其他任务前仍需用户授权。

优先用目标端口直接定位容器，再用监听信息交叉验证：

```bash
docker ps --no-trunc --filter publish=<宿主机端口> --format '{{.ID}}|{{.Names}}|{{.Status}}|{{.Ports}}'
fuser -v -n tcp <宿主机端口>
ss -ltnp | grep -E '(:<宿主机端口>)([[:space:]]|$)'
```

看到 `rootlesskit` 监听端口时，不要把它当作单个模型服务进程。它是 rootless 容器运行时的网络辅助进程，可能同时服务多个容器；为清理一个容器而结束整个 `rootlesskit`，可能中断同一用户的其他容器。

## 停止与删除 Docker 容器

本工作区采用以下语义：

- 用户说“杀掉”“结束”“清理”某个 Docker 或容器，且没有要求保留容器时，含义是停止并删除准确命名的容器；容器内进程会随停止而结束。
- 用户明确说“只停止”或“保留容器”时，只执行 `docker stop`。
- 不得把“杀掉容器”解释为结束整个 `rootlesskit`、`dockerd`、`containerd` 或该用户的全部容器运行时。

正常清理使用：

```bash
docker stop --time 10 <容器名或ID>
docker rm <容器名或ID>
```

多个已准确识别的容器可以在同一次操作中处理：

```bash
docker stop --time 10 <服务端容器> <客户端容器>
docker rm <服务端容器> <客户端容器>
```

- 只有正常停止失败且用户明确授权强制清理，或用户直接要求立即强制删除时，才使用 `docker rm -f`。
- 不使用 `docker rm -v`，除非用户明确要求同时删除卷。
- 删除容器不会删除镜像或宿主机 bind mount 中的数据，但会删除该容器的可写层和容器配置。
- 若容器停止后端口仍被 `rootlesskit` 保留，在删除该准确容器已获授权的前提下，直接执行 `docker rm <容器>`，然后验证端口；不要结束整个 `rootlesskit`。
- 出现临时 hosts 文件缺失等运行时警告时，不凭警告判断成败，直接检查容器是否仍存在以及端口是否释放。

用户说“项目暂停”或“项目结束”时，该口令授权清理当前实验自身的运行态：根据 `experiment.env` 与 `LOG.md` 精确枚举并停止、删除所有本实验 server、prefill、decode、router、client、benchmark、profiler 和 Nsys 容器；有证据表明属于本实验但已脱离容器的进程也应结束。清理不包含任何文件、目录、模型、镜像、bind mount 或结果删除，也不包含 `rootlesskit`/容器运行时和其他任务。清理后对所有目标主机执行统一验证。

## 统一验证

变更后只做一轮有针对性的验证：

```bash
docker ps -a --no-trunc --format '{{.ID}}|{{.Names}}|{{.Status}}|{{.Ports}}'
fuser -v -n tcp <宿主机端口>
ss -ltnp | grep -E '(:<宿主机端口>)([[:space:]]|$)'
nvidia-smi --query-compute-apps=gpu_uuid,pid,used_memory --format=csv,noheader,nounits
```

按目标筛选输出并确认：容器不存在或处于用户要求的状态、端口不再监听、对应 GPU 进程已消失。若审批窗口超时或远端连接中断，先把结果视为未知，做一次只读验证；状态仍不明确时最多重试一次同一个更窄的变更，然后向用户汇报，不切换到扩大影响范围的命令。

## 分工与远端工程

一级和二级调度不直接登录服务器。design的SSH用于指定工程文件编辑、静态检查、参与节点必要同步和白名单交付回收；资源现场、容器/服务/模型下载、GPU执行和清理由execute负责；analyze仅在授权结果上离线分析。命令都从实际远端版本执行，不要求本地源码镜像。
