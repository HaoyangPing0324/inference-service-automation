# 缺少精确教程时的迁移部署

先从平台sources收录入口取目标版本或模型族教程。模型族页已覆盖目标架构/尺寸时，不因没有独立专属命令而额外等待；未完全覆盖则在已授权资源内选合理迁移参数直接启动，简短注明参考来源和本地适配，不先制作完整证据表。不把类比称作官方保证。只有具体报错/不支持参数时再查对应CLI、源码或容器依赖，不在启动前全面审计。

## 未知硬件平台

1. 从已配置平台入口取可用启动方式，只快速确认目标设备/显存无冲突即可试跑。芯片映射、运行时、通信、挂载等根据命令实际需要或报错再核实，不作为全量前置清单。
2. 以同框架NVIDIA命令作功能基准，逐项映射模型路径、dtype/量化、TP/DP/EP/PP、KV cache、prefix cache、设备选择、通信、启动与健康接口。厂商官方安装/模型兼容/特殊指令优先于NVIDIA语法；不把CUDA参数原样搬到其他平台。
3. 对没有官方保证的组合，以显存预算、版本兼容和一次最小可验证启动形成候选。报错先定位层次（依赖/设备/模型加载/分布式/内存/服务/采集），记录原命令、错误和单项修正；不同时猜改多项。普通本任务内机械修复按已有授权执行，新增依赖、改变语义或影响他人仍按异常规则确认。

## 未知模型

1. 先从已有检查点config/模型卡取启动所需架构与dtype，沿用框架自动识别。专家、KV、量化、上下文或特殊代码仅在当前命令实际需要或出现相关错误时补查，不把全部模型特性审阅作为启动门槛。
2. 优先找目标平台同架构/同模型家族且版本匹配的部署方法；没有时找该平台其他模型的运行时协议，再以其他平台的同模型教程补模型特性。记录借鉴了哪一层，不把近似模型的TP、显存比例或性能数字直接继承。
3. 按权重、KV cache、运行时开销和可用显存估算并行规模及安全余量，核对框架CLI/插件支持。参数无唯一依据时作为待验证候选写进实验设计，在用户已有目标与资源范围内自行选定并试跑，不逐项索取批准；启动成功、真实chat、负载与采集分别验收。

## 双未知

先用NVIDIA命令明确模型语义，再用目标平台官方运行时资料替换硬件接口；把模型兼容和平台兼容分别列为假设。按显存与结构估算初版参数，每次只验证一个失败层次。无法证明兼容时如实停在已验证边界，不把可启动等同于正确或高性能。

平台特有的采集/导出流程、验收条件和脚本放在`platforms/<platform>/`的获批经验及对应实验的`client/`、`server/`，不要把NVIDIA Nsys脚本当作所有平台的默认采集器。可复用且经批准的脚本才提升到平台模板；版本不兼容时保留平台分支。问题、根因、解决和验证范围按[平台经验导航](../platforms/README.md)沉淀；未经批准的新结论仅存实验`LOG.md`与证据目录。
